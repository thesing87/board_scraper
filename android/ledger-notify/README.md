# YeYe홈 (안드로이드 앱)

휴대폰의 카드 결제 알림을 가계부의 **확인 대기함**으로 보내는 앱. 서버 쪽은 `app/ledger.py`의 연결 주소(`/api/ledger/hook/<키>`)를 그대로 씀.

- 결제 알림처럼 보이는 글(`O원` 금액 + 승인·결제·취소 같은 낱말)만 보냄 — 다른 알림은 휴대폰 밖으로 나가지 않음
- 인터넷이 안 되면 모아 두었다가 연결되면 다시 보냄 (휴대폰을 껐다 켜도)
- 같은 알림이 10분 안에 또 오면 한 번만
- 앱마다 끄기, 최근 보낸 알림과 서버의 답 보기, 시험 알림 보내기

## 금액 인식 알림 (1.5부터)

결제 알림을 가계부 확인 대기함에 넣으면 서버가 넣은 내용(`item`: 금액·가게·카드·취소·분류)을 함께 답하고,
앱이 휴대폰 알림으로 띄움 (예: `12,000원 · 스타벅스` / `신한카드 · 확인 대기함에 넣음 · 분류: 카페`). 누르면 앱의 확인 대기함으로.

- 설정 → '금액 인식 알림'(처음엔 켜짐), '못 보낸 것도 알림'(처음엔 꺼짐 — 인터넷이 안 될 때 금액만 알아본 결제. 나중에 보내지면 그 알림이 '넣음'으로 바뀜)
- 같은 알림이라 넘긴 것·결제 알림이 아닌 것은 알리지 않음. 2건 이상 쌓이면 '가계부 결제 N건'으로 묶임
- 안드로이드 13 이상은 알림 권한이 필요 — 알림 읽기 권한을 켠 뒤 처음 앱을 열 때 한 번 묻고, 거절하면 위쪽 할 일 줄에 '알림 권한 켜기'
- 서버를 먼저 배포해도 예전 앱(1.4 이하)은 늘어난 답을 무시함

## 무시할 알림 (1.5부터)

설정 → '무시할 알림'에 표현을 넣으면(예: `결제예정`, `적립`) 알림 글에 그 표현이 있을 때 가계부로 보내지 않음 — 휴대폰 밖으로 나가지 않고,
'최근 알림'에 "거름 ('결제예정')"으로만 남음. 이 휴대폰에만 저장(다른 휴대폰은 따로), 띄어쓰기·대소문자 무시, 50개까지.
'최근 알림'에서 보낸 알림의 **이런 알림 안 받기**를 누르면 그 글의 원문과 낱말(두 글자 이상, 숫자 빼고)이 나옴 (1.27부터):
원문을 끌어서 고르거나, 낱말 칩 두 개를 차례로 누르면 원문에서 그 사이를 통째로(`hi` → `pass` = `hi-pass`) 아래 칸에 넣고, 칸에서 고쳐 **거르기에 추가**.

## 가계부·근무표 탭 (1.6부터, 앱 이름 YeYe가계부 → YeYe홈)

아래쪽 탭으로 가계부(`/ledger/`)와 근무표(`/duty/`, 서버 `app/duty.py`)를 오감. 탭마다 웹 화면을 따로 둬서 오가도 보던 곳이 그대로이고,
로그인(가계부 쿠키)은 함께 씀. 근무표는 그 탭을 처음 볼 때 열고, 앱을 다시 열면 마지막으로 본 탭부터 (금액 인식 알림을 누르면 가계부).
뒤로가기는 페이지에 열린 것부터 닫고, 근무표 탭이면 가계부 탭으로. 보고 있는 탭을 다시 누르면 맨 위로.
패키지 이름(`kr.home.ledgernotify`)과 서명 키는 그대로라 예전 앱(1.5 이하)도 자동 업데이트로 바뀌고 결제 알림 연결도 이어짐.

## 고정 주소·전체 설정 (1.8부터)

- 앱이 여는 주소는 고정(`res/values/strings.xml`의 `site_url`, 서버 DDNS_URL과 같은 곳). 설정의 주소 칸은 없앰. debug 빌드만 `src/debug`에서 에뮬레이터용 `http://10.0.2.2:8765/ledger/`(이 PC의 시험 서버)
- 홈 탭 위쪽 '설정' = 전체 설정(`/yeye/#settings`, PC 브라우저에서도): 앱 파일(관리자 APK 올리기, 앱 밖의 멤버는 앱 받기), 이 휴대폰 앱(버전·새 버전 확인 `LedgerApp.checkUpdate/updateText`), 로그아웃(`LedgerApp.loggedOut`로 다른 탭도 다시 읽음)
- 가계부 설정의 '앱 파일' 탭은 없앰 (결제 알림 연결 칸의 앱 받기 버튼은 그대로)

## 홈 탭·탭마다 설정 (1.7부터)

- 아래쪽 탭은 **홈 | 가계부 | 근무표**, 앱을 열면 홈부터 (금액 인식 알림을 누르면 가계부, 근무표 위젯을 누르면 근무표)
- 홈은 서버의 요약 페이지 `/yeye/`(`/api/ledger/home`): 사람마다 오늘·내일 근무, '처음 보일 사람'의 이번 주 7일, 가계부 이번 달 지출·수입·확인 대기함·최근 3건. 카드를 누르면 그 탭으로 (`/ledger/#inbox`는 대기함으로)
- 위쪽 '설정'은 보고 있는 탭의 설정: 홈 → 앱 설정(가계부 주소·버전·로그아웃), 가계부·근무표 → 그 페이지의 설정 화면(`window.appOpenSettings`). 휴대폰 결제 알림 설정(알림 읽기 권한·연결 주소·무시할 알림·최근 알림)은 가계부 설정 > 결제 알림 연결의 '휴대폰 알림 설정 열기'
- 앱 안에서는 웹 머리줄의 설정·로그아웃 버튼을 숨김. 뒤로가기는 페이지에 열린 것 → 가계부·근무표면 홈 탭 → 홈이면 한 번 더 누르면 종료
- 다른 탭으로 가면 떠나는 페이지에 `window.appTabHidden()`(근무표 고치기 끝), 못 연 탭은 다음에 그 탭을 볼 때 다시 엶

## 홈 화면 근무표 위젯 (1.7부터)

- **근무표 · 한 달**(4×4쯤): 이번 달 달력에 날짜마다 근무 배지(웹과 같은 색), 위에 '오늘 E · 내일 N'. 낮게 줄이면 근무 글자 대신 칸을 근무 색으로
- **근무표 · 오늘**(2×1쯤): 오늘 근무 이름·시간과 다음 사흘
- 놓을 때 누구 근무표인지 고름(`DutyWidgetConfig`, 한 명뿐이면 묻지 않음), 안드로이드 12 이상은 위젯을 길게 눌러 다시 고름
- 데이터는 앱 안 가계부 로그인(쿠키)으로 `/api/ledger/duty`를 받아 위젯마다 저장 — 인터넷이 안 되면 저장한 것으로 그리고 구석에 '연결 안 됨'
- 새로: 3시간마다(`updatePeriodMillis`), 자정 조금 뒤(알람), 근무표 페이지에서 고쳐 저장하면 바로(`LedgerApp.dutyChanged()`), 앱을 닫을 때
- 근무 색을 그대로 쓰려고 위젯 크기만 한 그림(Bitmap)을 그려 넣음(`DutyWidgets`). 누르면 앱의 근무표 탭
- 한 달 위젯 달 넘기기 (1.24부터): 맨 위 '‹ 11월 근무 · 사람 ›'의 화살표로 지난달·다음 달, 다른 달을 보는 동안 오른쪽은 '이번 달로'.
  누를 자리는 그림 위에 투명하게 겹침(`layout/duty_month_widget.xml`, 제목 자리는 같은 글자를 투명하게 넣어 폭을 맞춤).
  위젯마다 보는 달을 저장(`v_위젯번호`)해 그 달을 받고, 자정 알람 때 이번 달로 돌아감
- 한 달 위젯 날짜를 누르면 앱 근무표에서 그 날짜 (1.25부터): 날짜 칸마다 투명한 누를 자리(`duty_d0`~`duty_d41`, 주 수만큼 줄을 보임)를
  겹치고, 누르면 `MainActivity`가 `EXTRA_DAY`·`EXTRA_PERSON`을 받아 근무표 페이지가 다 읽힌 뒤 `window.appOpenDay(날짜, 사람)`를 부름
  (그 사람·그 달로 가서 그날을 고름). 빈 칸은 그냥 앱 열기
- 배경 투명도 (1.25부터): 놓을 때·길게 눌러 다시 설정할 때 창에서 0~100%(10%씩), 위젯마다(`a_위젯번호`). 흰 배경만 투명해지고 글자·근무 색은 그대로
- 한 달 위젯 구분선 (1.25부터): 주마다 가로선 (날짜 사이 옅은 세로선은 1.26에서 뺌)
- 확인은 에뮬레이터(안드로이드 14, `D:\android\avd\yeye34`)에서: 이 PC의 시험 서버를 `http://10.0.2.2:포트`로 넣고 홈 화면에 위젯을 놓아 봄

## 근무표 변경 알림 (1.12부터, FCM)

- 누가 근무표에서 근무를 넣거나·바꾸거나·지우면, 서버(`app/duty_push.py`)가 **고친 사람을 뺀 모두**의 휴대폰에 Firebase Cloud Messaging으로 알림을 보냄. 잇달아 고친 것은 30초 조용해지면 근무표 주인·고친 사람마다 하나로 모음 ('근무표 변경 · 예예 / 지은님이 고침 / 12/3(목) 데이 → 나이트'), 되돌린 날은 뺌
- 앱이 로그인하면(페이지를 읽을 때·앱을 켤 때) FCM 토큰을 `/api/ledger/duty {action: push-token}`으로 등록(`DutyPush`). 토큰은 서버에서 로그인 기기에 묶여 로그아웃·허락 취소 때 함께 지워짐
- 앱이 뒤에 있으면 시스템이 채널 '근무표 변경 알림'(`duty_change`)으로 띄우고, 앞에 있으면 앱이 띄움. 누르면 근무표 탭
- 홈 > 설정 > '근무표 변경 알림 (이 휴대폰)'에서 끄면 서버에서 이 휴대폰 토큰을 지움
- 빌드에는 Firebase 콘솔에서 받은 `app/google-services.json`(git에 안 올림, PC마다 복사)이 있어야 함. 없으면 알림 받기 없이 빌드되고 설정에 카드가 안 보임. 정식(`kr.home.ledgernotify`)·시험(`kr.home.ledgernotify.test`) 두 앱을 모두 Firebase에 등록한 파일이어야 qa 빌드도 됨
- 서버는 Firebase 서비스 계정 키를 `output/fcm-service-account.json`(또는 `.env`의 `FCM_SERVICE_ACCOUNT` 경로)에서 읽음. 없으면 보내지 않음

## 가계부 변경 알림 (1.14부터, FCM)

- 누가 가계부에 기록을 넣거나·고치거나·지우면(결제 알림 대기함 확정·취소 확정 포함), 서버(`app/ledger_push.py`)가 **고친 사람을 뺀 모두**에게 알림. 관리자가 남의 기록을 고치면 그 주인도 받음
- 기록이 바뀔 때마다 `ledger_changes`에 그때의 기록(전·후)을 남기고, 30초 조용해지면 고친 사람마다 하나로 모음 ('가계부 · 지은님 / 등록 11/24(화) 식비 12,000원 · 스타벅스 / 수정 11/23(월) 교통 3,000원 → 4,500원'). 넣었다 지운 것·되돌린 것은 뺌, 8건 넘으면 '외 n건'
- 채널 '가계부 변경 알림'(`ledger_change`), 누르면 가계부 탭. 홈 > 설정 · 앱 설정에서 근무표 알림과 따로 켜고 끔
- 토큰을 등록할 때 `{duty, ledger}`로 받을 알림을 함께 보냄. 둘 다 끄면 서버에서 토큰을 지움. 예전 앱(1.13까지)은 근무표 알림만 받음

## 근무표 달력에 구글 캘린더 일정 (1.16부터)

- 근무표 > 설정 > '구글 캘린더'에서 켜면 앱이 캘린더 읽기 권한(`READ_CALENDAR`)을 묻고, 휴대폰에 연결된 계정(구글 등)의 캘린더 일정을 `CalendarContract`로 읽어 근무표 달력에 함께 보여 줌 (`PhoneCalendar`). 구글 로그인·서버 저장 없이 읽기만, 그래서 **그 휴대폰에서만** 보임
- 달력 칸마다 근무 배지 아래 일정 이름 휴대폰 3개·넓은 화면 4개까지(작은 글자, 왼쪽에 캘린더 색 띠, 넘으면 아래 오른쪽에 +n,
  칸이 넓으면 시작 시각도 — 휴대폰에서는 이름만), 아래 칸에 고른 날(처음엔 오늘)의 근무와 일정. 고치기 중에는 숨김
- 근무표 위젯에도 (1.18부터, 같은 켜기·캘린더 보이기 설정을 따름): 한 달 위젯은 근무 배지 아래 남는 높이만큼 일정을 한 줄에 하나씩
  (1.20부터, 다 못 넣으면 마지막 줄에 +n), 칸이 낮으면 맨 아래 색 띠만. 근무 배지는 일정이 있든 없든 같은 크기·자리.
  작은 위젯은 오늘 근무 아래 '● 10:00 병원 ● 19:00 운동 외 1' 한 줄, 위젯이 높으면 한 줄에 하나씩 높이만큼 (위젯 높이가 낮으면 생략).
  캘린더가 바뀌면 `CalendarWatch`(JobScheduler 내용 변경 트리거)가 5초~1분 뒤 저장해 둔 근무표로 다시 그림
- 여러 날 일정은 삼성 달력처럼 칸 사이까지 이어진 하나의 띠 (페이지는 서버 배포만, 한 달 위젯은 1.21부터): 주마다 잘라 다음 주 첫 칸에서
  다시 이어 그리고(이어지는 쪽 끝은 각지게), 같은 주에서는 먼저 시작한 것·긴 것부터 위 줄, 같은 일정은 그 주 안에서 같은 줄
  (`duty.js` weekSegments·placeBars, `DutyWidgets.segments`). 띠 줄 아래에 하루 일정. 근무가 없는 날도 배지 자리를 비워 띠 높이를 맞춤.
  날짜·근무 배지는 크게, 일정은 작게 (페이지 휴대폰 날짜 11·배지 10·일정 8px, 넓은 화면 12·11·8.5px, 위젯은 1.22부터 모든 글자를
  2씩 키워 날짜·근무 14·일정 10·제목 15dp — 칸 높이 50dp쯤부터 일정 한 줄, 1.24부터 1씩 더 키워 날짜·근무 15·일정 11·제목 16dp,
  작은 위젯 근무 19·일정 13dp).
  잘리는 일정 이름은 아랫줄에 이어서 두 줄까지 (페이지는 CSS line-clamp, 칸에 다 안 들어가면 fitCells가 아래 것부터 숨기고 +n에 더함,
  위젯은 `wrap`). 여러 날 일정 띠도 이름이 한 줄에 안 들어가면 두 줄 (페이지·위젯 1.23부터): 그 주의 그 띠 줄 전체를 두 줄 높이로 해서
  같은 줄의 띠·아래 일정이 어긋나지 않게 (페이지는 placeBars가 재서 st.two에 넣고 다시 그림, 위젯은 laneH)
  페이지의 일정 칸 높이는 px로 막지 않고 줄 수(line-clamp)와 `lh`로만 정함 — 휴대폰 글자 크기를 키우면 px 높이에서 둘째 줄 아래가 잘렸음
- 설정에서 캘린더마다 보이기·숨기기 (휴대폰 캘린더 앱에서 숨긴 캘린더는 목록에서 뺌). 반복 일정은 날마다
- 페이지는 `LedgerApp.calendarState()`·`calendarEvents(from, to)`·`setCalendarOn`·`setCalendarShown`·`askCalendar`를 부르고, 앱은 권한·설정이 바뀌거나 앱으로 돌아오면 `window.appCalendarChanged()`를 부름. 브라우저·예전 앱(1.15까지)에서는 아무것도 안 바뀜

## 앱 화면 (1.2부터)

앱을 열면 가계부 페이지(`가계부 주소`, 설정에서 넣거나 연결 주소에서 만듦)가 앱 안에 뜨고 그대로 조작함.
위쪽 줄에 새로고침·설정, 그 아래 할 일 한 줄(알림 읽기 권한이 꺼짐·새 버전 설치 허용·앱 연결 전 등).

- 가계부 로그인은 앱 안에서 한 번 하면 유지됨 (쿠키)
- 가계부 페이지는 `window.LedgerApp`으로 앱을 알아보고 '결제 알림 자동 기록'에 **이 휴대폰 앱에 연결**을 보여 줌 —
  누르면 새 연결 주소를 만들어 앱에 바로 넣음 (주소 복사·붙여넣기 없이). 같은 가계부 주소의 페이지에서만 받음
- 가계부가 아닌 주소의 링크는 브라우저로 열림. 앱 안에서 '가계부 알림 앱 받기'를 누르면 받지 않고 바로 새 버전 확인

## 배포 (가계부 페이지로)

빌드한 `app-release.apk`를 가계부의 관리자 칸 → '가계부 알림 앱 파일 (APK)'에서 올리면, 가계부를 쓰는 사람 모두가
'결제 알림 자동 기록' → **가계부 알림 앱 받기**로 받음 (`app/ledger_app.py`, 파일은 `output/ledger_app/`).
올릴 때 APK 안의 패키지 이름(`kr.home.ledgernotify`)과 버전을 확인하고, 지금 올라가 있는 것보다 낮은 버전은 거절함.

**서버 배포(`deploy\deploy.ps1`)로 함께 올리기:** 배포 끝에 이 PC에 빌드한 `app\build\outputs\apk\release\app-release.apk`가 있으면
- 패키지가 `kr.home.ledgernotify`이고 서명이 원래 키(인증서 SHA-256 `ddb6e2c7…eea8`)인지 apksigner로 확인 (임시 시험 키면 올리지 않음)
- 서버에 올라간 것보다 `versionCode`가 높을 때만 웹 컨테이너에 넘겨 위와 같은 확인을 거쳐 바꿔 끼움 (`deploy/app_apk.py`, 올린 사람은 '배포(PC)')
- 결과는 배포 끝에 `[앱] 1.9(10) 올림` / `[앱] 서버에 이미 … - 앱은 그대로`처럼 한 줄
- 안드로이드 도구는 `C:\android`(회사 PC) 또는 `D:\android`(집 노트북)에서 찾음. 웹에서 올리는 방법도 그대로 됨

그래서 새 버전은 `versionCode`를 올려 `assembleRelease`로 빌드하고 커밋·push한 뒤 배포만 하면 됨.

## 자동 업데이트 (1.1부터)

앱을 열면(10분에 한 번) 연결 주소로 가계부에 올라간 앱 버전을 확인(`<연결 주소>/app`)하고, 지금보다 새것이면
받아서(`<연결 주소>/app.apk`, sha256 확인) PackageInstaller로 설치함.

- 처음 한 번은 '이 앱의 설치 허용'(출처를 알 수 없는 앱)을 켜야 함 — 앱 화면에 버튼이 뜸
- 안드로이드 12 이상에서는 앱이 자기 자신을 고치는 것이라 확인 창 없이 설치될 수 있고, 그 밖에는 '업데이트' 확인 창이 뜸
- 확인 창은 보이는 앱 화면 안에서 띄움 (1.17부터 — 앱 밖으로 띄우면 앱이 막 켜지는 중에 앱 화면에 가려 저절로 닫히곤 했음).
  앱 화면이 없으면 다음에 앱을 열 때 띄움
- 확인 창에서 취소하면 그 버전만 하루 동안 자동으로 묻지 않음 ('새 버전 확인'을 누르면 바로, 1.19부터 더 새 버전이 나오거나 앱이 새 버전으로 바뀌면 취소 기록을 지움 — 그 전에는 앱을 올려도 남아 다음 버전까지 막았음). 뜨고 3초 안에 닫힌 것은
  취소로 치지 않고 다시 띄움 (2번까지, 그 뒤로도 닫히면 '새 버전 확인'을 누르라고 안내)
- 새 버전은 `versionCode`를 올리고 **같은 키로 서명**해 서버 배포(위)로 함께 올리거나 가계부 관리자 칸에 올리면 됨

## 설치

1. 가계부에서 **가계부 알림 앱 받기** → 받은 파일 열기 → '출처를 알 수 없는 앱' 설치 허용
2. 앱을 열고 **알림 읽기 권한 열기** → '가계부 알림' 켜기
   - 회색이라 안 켜지면(안드로이드 13 이상): **앱 정보 열기** → 오른쪽 위 ⋮ → **제한된 설정 허용** → 다시 켜기
3. **배터리 사용 '제한 없음'으로**
4. 가계부 → '결제 알림 자동 기록' → '연결 주소 만들기' → 복사 → 앱에서 **붙여넣기**
5. **시험 알림 보내기** → 가계부 확인 대기함에 1,000원 시험 결제가 뜨면 끝

## 빌드 (Windows)

정식 릴리즈는 **집 노트북**과 **회사 PC** 두 곳에서 함. 구성은 같고 드라이브만 다름 (안드로이드 스튜디오 없이).

| | 집 노트북 | 회사 PC |
|---|---|---|
| 도구·키 폴더 | `D:\android` | `C:\android` |
| JDK 17 | `D:\android\jdk17` | `C:\android\jdk17` |
| Gradle 8.7 | `D:\android\gradle-8.7` | `C:\android\gradle-8.7` |
| SDK 34 | `D:\android\sdk` | `C:\android\sdk` |
| 원래 서명 키 | `D:\android\keys` | `C:\android\keys` |

### 처음 한 번 (PC마다)

`keystore.properties`·`local.properties`는 git에 안 올라가므로 PC마다 따로 둠.

1. `<폴더>\keys\keystore.properties`를 이 폴더(`android/ledger-notify`)에 복사하고 `storeFile`을 그 PC 경로로 고침
   - 집 노트북: `storeFile=D:/android/keys/ledger-notify.jks`
   - 회사 PC: `storeFile=C:/android/keys/ledger-notify.jks`
2. Firebase 설정: `<폴더>\keys\google-services.json`을 `app\google-services.json`으로 복사 (근무표 변경 알림)
3. `local.properties`에 `sdk.dir`
   - 집 노트북: `sdk.dir=D\:/android/sdk`
   - 회사 PC: `sdk.dir=C\:/android/sdk`

### 릴리즈 빌드

회사 PC 기준. 집 노트북에서는 `C:`를 `D:`로 바꿔서 실행.

```powershell
$env:JAVA_HOME = 'C:\android\jdk17'
C:\android\gradle-8.7\bin\gradle.bat assembleRelease --no-daemon
# → app\build\outputs\apk\release\app-release.apk
C:\android\sdk\build-tools\34.0.0\apksigner.bat verify --print-certs app\build\outputs\apk\release\app-release.apk
# → CN=Ledger Notify, 인증서 SHA-256 ddb6e2c7a013a2c3e4ee8b2b7e169eb3a74768e16a1029c1aef612222918eea8 이어야 덮어 설치됨
```

### 두 곳에서 번갈아 릴리즈할 때

- 빌드 전에 `git pull`로 최신 코드를 받음 (두 PC가 같은 코드로 빌드하도록)
- 새 버전을 낼 때는 `app/build.gradle`의 `versionCode`를 올리고 **바로 커밋·push** — 다른 PC에서 같은 번호를 다시 쓰지 않게. 번호가 같거나 낮으면 휴대폰에 덮어 설치되지 않음
- 두 곳의 키 파일은 **같은 파일**이어야 함 (인증서 지문이 위와 같은지 확인). 키를 잃어버리면 앱을 지우고 다시 설치(설정도 다시)해야 하니 두 곳 중 한 곳에 늘 백업이 있게 둘 것
- 만든 APK는 서버 배포(`deploy\deploy.ps1`) 때 함께 올라감 (위 '배포' 참고). 웹으로 올릴 때는 전체 설정 > 앱 파일에서

### 시험 앱 (qa 빌드, 정식 키가 없을 때)

정식 앱 옆에 따로 설치되고, 가계부 관리자 칸에는 올라가지 않음 (패키지가 달라 거절됨).

- 서명은 임시 키 `keystore-test.properties` → `C:\Users\thesi\android-keys-temp\ledger-notify-test.jks` (회사 PC, git에 안 올림). **정식 릴리즈에는 쓰지 않음**
- 시험 앱의 연결 주소는 정식 앱 설정의 연결 주소를 그대로 붙여 넣을 것 — 가계부에서 '이 휴대폰 앱에 연결'(새 연결 주소)을 누르면 정식 앱의 주소가 막힘
